## Mend 1.0.11 — 15 Oct 2026

- **Linux amd64 is cross-compiled now, not emulated:** one build image for the Mac's own architecture holds a full amd64 Debian sysroot (the GTK/WebKitGTK stack downloaded and unpacked under `/sysroot/amd64`, never executed) and the cross gcc; cargo links against it with `--sysroot`, so the amd64 `.deb` builds at native speed in a few minutes instead of 70+ under QEMU, where gcc crashed. Only the AppImage packer (linuxdeploy) still needs emulation and stays best-effort. Tested here with the mirror-image setup (x86_64 host → arm64 sysroot): a signed `Mend_arm64.deb` in 2m45s, ARM binary, correct NEEDED libraries and Depends.
- **amd64 Linux under Rosetta, not QEMU:** the first amd64 container build took 72 minutes under QEMU and its AppImage packer (linuxdeploy) failed. update.sh now switches Rosetta on itself — colima is restarted with `--vm-type vz --vz-rosetta`, Docker Desktop gets “Use Rosetta for x86_64/amd64 emulation” turned on and is restarted — and the AppImage is packed in a second, verbose step with `NO_STRIP`; if it still fails the `.deb` is published and latest.json keeps the previous AppImage instead of the whole release stopping.
- **Homebrew's docker CLI has no BuildKit:** `docker build` fell back to the legacy builder and rejected `--progress`. update.sh now installs `docker-buildx` and links it as a CLI plugin (Docker Desktop users already have it), and only passes `--progress=plain` when buildx is there. Finished Windows/Linux installers for the current version now survive a rerun (release/ is no longer wiped whole).
- **Linux builds on the Mac, fixed and tested:** the build packages are now installed once into a reusable image (`scripts/linux-build.Dockerfile` + `scripts/linux-deps.sh`) instead of on every run; apt's real error is printed when something fails (it was hidden behind `dpkg returned an error code (1)`), with an automatic repair-and-retry and a workaround for the emulator crash that most often breaks amd64 package installs on Apple silicon; Node.js falls back to the official nodejs.org build if NodeSource fails; the container gets `CI=true` (the Tauri CLI rejects `CI=1`); arm64 builds first (native, fast); each architecture builds into its own folder with a kept Rust cache and crate volume, so reruns are quick; installers already built for this version are kept on a rerun.
- **Windows ARM64 build on a Mac:** `ring` assembles its ARM64 Windows code with plain `clang`, which rejects the clang-cl `/imsvc <dir>` header flags cargo-xwin sets (“no such file or directory: '/imsvc'”). update.sh now puts a tiny clang shim first in PATH during the Windows builds that rewrites `/imsvc` to `-isystem`.
- **Windows build on a Mac whose home folder has a space:** cargo-xwin keeps the Windows SDK under `~/Library/Caches/cargo-xwin` and joins its library paths into RUSTFLAGS with spaces, so a home like `/Users/Jagadeesh Kumar S` failed with “flag in rustflags must not contain its separator”. update.sh now keeps that cache at `/Users/Shared/cargo-xwin` (moving an already-downloaded SDK there) — `XWIN_CACHE_DIR` overrides it.
- **Every installer from the Mac, no GitHub Actions:** `update.sh` now installs what the Windows and Linux builds need when it is missing (cargo-xwin, NSIS, LLVM; Docker Desktop if present, otherwise colima + the docker CLI, started headless with Rosetta) and stops the release if a Windows or Linux build fails instead of quietly leaving it to CI. The CI workflow runs only with `--ci`; `--mac-only` publishes just the Mac builds on purpose. (The 1.0.10 run shipped only the DMGs because cargo-xwin, makensis and Docker were not on the Mac.)
- **Menu bar drop-downs:** new **Devices** (every connected phone/tablet, refresh, restart the USB service, back up now) and **Disks** (every disk with its health, full report, save a report for every disk, Disks & Partitions, duplicates) menus that follow what is connected; **Repair** and **Back Up** menus; View → Animations and View → Language (15 languages); Window → Mend Lives In (Dock / menu bar / background) and a test notification; Help → Star Mend on GitHub, Install with Pour (copies the two lines), Open the Log Folder, Helpers & Log.
- **`bash update.sh` no longer stops at the Rust tests on a Mac where Mend is running:** the single-instance test connected to the real `~/Mend/mend-<uid>.sock`, handed its arguments to the running app and reported a failure. It now uses a temporary socket (and a second test proves the hand-over round trip). Nothing had been published on 14 Oct because of it; the next run goes through.
- **Contacts → AI tidy (new tab):** short, meaningful names (drops emojis, numbers, "work/new/old", repeated words and shouting, keeps Tamil/Hindi/Arabic script) and notes summarised to two lines — proposed by the AI Mend already uses (a local model on the Mac keeps everything on the computer; the built-in free one otherwise), shown as before → after rows you tick before anything is saved. A summary that loses a phone number, date or amount is thrown away. Also in the right-click Repair menu.
- **Fixed the 1.0.9 crash that made Settings unreachable on the owner's Mac** (10 reports: `rc@index-CnL1QT0J.js` ReferenceError and the `insertBefore` NotFoundError that followed): the Settings dialog read a value before it was declared, so every open of Settings threw inside render and left the window half-drawn. Settings opens again for owner, Pro and free; the Playwright page-error hunt now covers every dialog in owner and Pro mode and in a non-Latin language.
- **Disk Health judged against real drives:** laptop and USB hard disks are rated on 300,000 start-stop cycles, not 50,000, and a worn counter never drags the estimate below 20 % by itself — only damage does (a WD10SPCX with 119,000 start-stops now reads about 60 % left, not 0 %). A four-state **SMART status** — OK · Warning · Failing · Failed — stands beside the gauges and in the report, so a Seagate with 456 remapped, 1,064 pending and 10,000 reported uncorrectable errors says FAILED like the drive itself does. A USB drive that gives no SMART data shows “no data”, never “100 % good”. New findings: heads parking many times an hour (→ APM 254), spinning down all day (→ standby off), minutes spent over the temperature limit, thousands of CRC errors flagged as cable/bridge. Thousands of CRC errors cost at most 8 points.

### Install

- **macOS** (Apple silicon and Intel): `curl -fsSL https://ipconfig.co.network/updates/mend/install.sh | bash`
- **Windows** (PowerShell): `irm https://ipconfig.co.network/updates/mend/install.ps1 | iex`
- **Linux** (AppImage): `curl -fsSL https://ipconfig.co.network/updates/mend/install.sh | bash` — add `-s -- --deb` for the .deb

First launch on macOS after a manual DMG install: `xattr -cr /Applications/Mend.app` (Mend is ad-hoc signed, not notarized).
